# Gate 17 — provider-blind prompt detector (delivery integrity)

**Status:** OPEN · HIGH

**FIELD SEMANTICS ARE ALSO BROKEN, same root:** measured on one lane's inbox — 15 of 18 records carry `delivered=true` AND `dead=true` **simultaneously** (dead-lettered after 5 attempts, then marked delivered anyway), while `delivered=false` covers both attempted-and-failed and never-attempted. So **neither value proves receipt**, and my own adopted practice of "read the delivered field" is wrong too. Fix must model **terminal/dead, attempted, submitted, acknowledged as SEPARATE states**, not one overloaded boolean. Until then, receipt is only established by an explicit reply or transcript correlation. — `lib/comms.sh:198` `fleet_input_busy()` greps a FIXED STRING for one provider's prompt glyph only. A pane using the other glyph never matches, so the landed-check stays false, `:316-321` takes the `never-landed` branch and REQUEUES a message that actually submitted. That is the root cause of the duplicate advisories, the `delivered=false` records, and the attempt-counting health metric — one defect, three symptoms. Also: the comment at `:194-195` claims a missed read errs toward delivering and never toward never-delivering; on this path it does the opposite, so the stated fail-safe DIRECTION is not the direction the code has. NOT PATCHED BY ME, deliberately: this is the live transport for every lane, and a bad edit costs the ability to talk to any lane including to report the breakage — asymmetric against acting while you are away, and the cost of waiting is duplicate messages, not lost work. Fix needs provider-aware glyph matching plus controls proving, for BOTH glyphs: busy-detect, success ack, no duplicate, and following-message flow. **DOES NOT SUPERSEDE THE METRIC/STATE ITEM — they are distinct.** The glyph fix removes the false never-landed path for THIS incident, but three defects survive it for genuine failures: `comms.sh:518` writes `delivered=true`+`dead=true` on dead-letter (so dead-letter reads as receipt), `comms.sh:567` accumulates `inject_failures` per failed drain ATTEMPT, and `bin/fleet:2271/:2277` report that accumulator as message failures and equate `delivered=false` with undelivered. **FRAMING FOR WHOEVER FIXES THIS — SCOPED, not universal. MEASURED on this corpus: the content ARRIVES. All 19 records on one lane read `delivered=true, attempts=5, dead=true`, and every text was present in that lane's thread. The transport SUBMITTED each message, failed to RECOGNISE the submission, retried (hence the duplicates), then dead-lettered and marked it delivered. The MEASURED defect is ACKNOWLEDGEMENT, STATE and HEAD-OF-LINE DELAY — not non-delivery. **BUT DELIVERY INTEGRITY IS UNTESTED AND THE SAME DEFECT DISABLES ITS GUARD:** `fleet_input_busy` is also the DEFER gate at `comms.sh:236`, whose stated job (`:183`) is to refuse to paste onto an input box holding real content — a human mid-typing, or a prior inject still unsubmitted. On a non-matching glyph it returns not-busy, so the gate NEVER defers and a paste can land on top of existing input and garble it. Atomic bracketed paste (`:267-277`) prevents interleaving WITHIN one paste; it does not stop pasting ONTO pre-existing content. So content may arrive CONCATENATED or CORRUPTED, and a lane's reply proves something was seen — not its path, completeness, ordering, or timeliness. Keep delivery-integrity controls for both glyphs, occupied input, and following-message flow.** ACCEPTANCE must include: one message retried N times ⇒ **messages=1, attempts=N**; dead-letter MUST NOT mean receipt; and terminal/dead, attempted, submitted, acknowledged modelled as separate states.
